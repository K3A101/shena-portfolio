# Shena portfolio

Static portfolio site for Shena, a bouwkunde (architectural engineering) student. The portfolio is organised around four **competenties**, each with numbered **leerdoelen**. Projects show which leerdoelen they demonstrate.

Plain HTML, CSS and vanilla JS: no framework, no dependencies. The HTML pages are generated by `build.py`, which needs only the Python 3 standard library. Open `index.html` in a browser to view the site.

## Build

```sh
python3 build.py
```

**All HTML pages are generated:** `index.html`, `reflectie.html`, `competenties/*.html` and `projects/*.html`. Never edit them directly, because the next build overwrites them. To change content or markup, edit `build.py` and run it again, then commit the script and the regenerated pages together.

## Language

The whole site is in **Dutch** (`<html lang="nl">`). This covers all visible text, `aria-label`s, `alt` text, meta descriptions and HTML comments meant for the content editor. Use correct Dutch spelling, e.g. "Digitale fabricage" (not "fabrikage").

## Site structure

There are three levels of pages, plus one standalone page:

```
index.html                         Home: hero, competentie cards (#competenties), timeline (#tijdlijn), contact (#contact)
reflectie.html                     Standalone STAR-reflectie on the whole portfolio
competenties/<slug>.html           Competentie page: its leerdoelen, then cards for every linked project
projects/<project-slug>.html       Project page: case study + the leerdoelen it demonstrates
```

| # | Slug | Competentie | Leerdoelen |
|---|---|---|---|
| 1 | `digitale-expert` | De digitale expert: onderzoeker & uitvoerder | 1.1–1.4 |
| 2 | `teamspeler` | De teamspeler in digitale context | 2.1–2.3 |
| 3 | `zelfsturende-professional` | De zelfsturende digitale professional | 3.1–3.3 |
| 4 | `professioneel-handelen` | Professioneel handelen HBO | 4.1 (+ diagram) |

**Projects are linked to leerdoelen, not directly to competenties.** A project appears on the page of every competentie that one of its leerdoelen belongs to. The competentie of the project's **first** leerdoel is its primary one. The primary competentie sets the breadcrumb, the "Terug naar competentie …" button and the "Volgende" link.

**Tags** are the specialisations: Parametrisch ontwerpen, ArcGIS, Digitale fabricage and Python. They are labels on project cards and project pages only, and have no pages of their own.

## Editing content in `build.py`

All content lives in data structures at the top of `build.py`. The order in each one is the order shown on the site.

**`REFLECTIE`:** the reflectie page is a **STAR-reflectie**: Situatie, Taak, Actie, Resultaat. Its fields are `title`, `lead` and `sections`. Each section has a `letter` (shown as a badge before the heading), a `heading` and `paragraphs`, a list of plain-text strings with one string per paragraph. Keep the STAR order.

**`TIMELINE`:** `start` and `end` months (`"YYYY-MM"`, inclusive) of the home-page **timeline slider** ("Mijn ontwikkeling", `#tijdlijn`, between the competenties and contact). It currently covers september 2026 – januari 2027. The slider is generated by `timeline()` from `PROJECTS`:
- Only projects whose `date` falls within the range appear. They are sorted oldest first, and projects in the same month keep their order in `PROJECTS`.
- Each card links to its project page.
- Each card shows a progress bar of how many leerdoelen have been demonstrated so far, counting this project and all earlier ones (out of all leerdoelen), and which leerdoelen are new in that project.
- Without JS the track is a scrollable list. `js/main.js` adds the prev/next buttons (`[data-slider]`, `[data-slider-track]`, `[data-slider-prev]`, `[data-slider-next]`) and hides them when everything fits.

The nav menu, in the `page()` function, has these items: Home, Competenties, Reflectie, Contact.

**`COMPETENTIES`:** `number`, `slug`, `name` and `leerdoelen`, a list of texts. Their codes (`"1.1"`, `"1.2"`, …) come from their position in the list, so **reordering or inserting leerdoelen changes the codes** that projects refer to. Optionally, a competentie can have a `diagram` (`image` in `images/`, `alt`, `caption`) shown below its leerdoelen. Competentie 4 uses this for the "professioneel handelen HBO" diagram. Until `image` is set, a placeholder is shown.

**`TAGS`:** key → display name.

**`PROJECTS`:**
- Required: `slug`, `title`, `leerdoelen` (a list of codes, primary first), `tags` (keys from `TAGS`), `lead`, `role`, `date` (`"YYYY-MM"`, shown as e.g. "oktober 2026" under "Periode"), `tools`.
- Optional: `challenge`, `process`, `steps` (a list; `[]` hides the list), `result`, `image` (a file name in `images/` or a full `https://` URL), `image_alt` (Dutch alt text, required when there is an image), `caption`.
- Without `image`, a project shows a stand-in photo from picsum.photos, seeded with the project slug so the photo stays the same between loads. The hero also uses a Picsum photo (the `picsum()` helper). Replace these with real images before publishing. All images have rounded corners (`--radius-lg`).
- Any optional text left out falls back to placeholder text from `CONTENT_DEFAULTS`.
- All text is HTML-escaped, so write plain text, not HTML.
- An unknown leerdoel code or tag key, or a badly formatted `date`, stops the build with an `error:`.

From that data the script fills in everything that repeats across pages:
- leerdoel and project counts on the home page
- project cards on each competentie page, showing which of that competentie's leerdoelen the project covers
- breadcrumbs and the "Terug" and "Volgende" links
- the "Andere competenties" list
- the "Aangetoonde leerdoelen" list on project pages

If a competentie has no projects, its page says so. The shared page shell (header, nav, footer, skip link) is the `page()` function, so a change there applies to every page.

**Renaming or removing** a project or competentie doesn't delete its old HTML file. The build prints a `warning:` line for each leftover file. Delete those files by hand.

## CSS

- `css/variables.css` holds the design tokens: colors, type scale, spacing, radius and transitions. Always use these tokens instead of hard-coded values. `1rem = 10px`, because `base.css` sets `html { font-size: 62.5% }`.
- `css/base.css` holds the reset, typography and utilities like `.visually-hidden` and `.skip-link`.
- `css/style.css` holds the layout and components, in BEM-style naming (`block__element--modifier`).
  - `.project-card` is used for both project cards and competentie cards (`.project-card.theme-card`). The `theme-*` class names are kept from the earlier theme-based layout. The whole card is clickable through `.project-card__link::after`, which keeps it to one link per card for accessibility.
  - `.leerdoel-list` / `.leerdoel` / `.leerdoel__code` / `.leerdoel__text` style the numbered leerdoelen on both the competentie and project pages.
  - Other components: `.theme-header` and `.theme-nav` (competentie page), `.project-detail*` and `.project-nav` (project page), `.breadcrumb`, `.tag-list`/`.tag`, `.button--primary`/`.button--outline`.
- Styles are mobile-first, with one breakpoint at `48em`.

## JavaScript

`js/main.js` is loaded with `defer` on every page. It:
- swaps the `no-js` class on `<html>` for `js`
- runs the mobile nav toggle (with `aria-expanded` and closing on Escape)
- fills the footer year (`[data-year]`)
- adds prev/next buttons to sliders (`[data-slider]`)
- fades in `.reveal` elements on scroll with an IntersectionObserver, skipped when the user prefers reduced motion

The site must keep working without JS.

## Accessibility conventions

- Keep the skip link, landmark elements, one `h1` per page, and an `aria-labelledby` on each section.
- Breadcrumbs are a `nav aria-label="Kruimelpad"` holding an `ol`, with `aria-current="page"` on the last item.
- External links open in a new tab and include a visually hidden "(opent in een nieuw tabblad)".
- On a project page, the image needs a meaningful Dutch `alt` (`image_alt`). On project cards the same image is decorative (`alt=""`), because the card title already names the project.
